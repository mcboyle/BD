## 1. Key architecture findings (measured -- these shape everything)

1. **CSRF is a global `before_request` hook AND a per-view call.** `_check_csrf`
   is `@app.before_request` (blanket enforcement of state-changing `/api/`, incl. a
   cross-origin Origin check) *and* invoked in 163 view bodies (defense-in-depth).
   Its body (L601-674) has **zero `app` references** -- the only `app` token is its
   own decorator. It moves cleanly to a leaf module; only the *registration* stays
   app-bound.

2. **The real challenge is shared mutable state, not CSRF.** Four module-global
   singletons are read/written across domains: `s_cfg` (in-memory sites config,
   **59** domains), `runners` (live `SiteRunner` registry, **25**), `_app_cfg`
   (**7**), `s_meta` (**6**).

3. **The established way to reach app-level state from an imported module is a
   lazy import inside the function body** -- proven in `runner.py`
   (`from .app import _save_sites_config` inside a method, deferred to call time).
   The **9 existing blueprints touch none of these singletons** -- they read config
   files / query the DB / render. Extraction has *already* been done without a state
   hoist.

   **Decision (low-risk):** **state stays in `app.py`; behavior (views) moves; the
   minority of state-touching views lazy-import the singletons.** No big-bang state
   move; the singletons keep their identity (one object, in `app.py`) -- provably.
   A later, separately-scoped motion may hoist state to `app_state`; not required
   (the bulk is 681 view *bodies*, not 47 small globals).

4. **The kernel is tiny.** `_check_csrf` is the only broadly-shared helper (72
   domains); next tier (`_save_sites_config`, `_validate_path`, `_build_meta`,
   `_do_action_all`) hits 3-4; everything else is 1-2 domains and travels with its
   domain. `app_common` starts as the **CSRF kernel only** (+ optionally the *pure*
   `_validate_path`/`_build_meta` once purity is confirmed). State-mutating shared
   helpers stay in `app.py` (lazy-imported), so `app_common` is a clean leaf.

5. **13 app-level hooks are irreducibly app-bound** (stay in the shell):
   errorhandler (7) `_on_attribute_error _on_bad_request _on_not_found
   _on_method_not_allowed _on_request_too_large _on_internal_error
   _method_not_allowed_parity`; before_request (3) `_check_token _check_csrf
   _dev_metrics_start`; after_request (3) `_add_security_headers _dev_metrics_record
   _bootstrap_session`. When `_check_csrf` moves, the shell keeps
   `app.before_request(app_common._check_csrf)`. **No new blueprint may register any
   app-wide hook** (the 9 existing register none -- confirmed).

6. **`CFG_FIELDS` (and `DEFAULTS`) are PINNED to `app.py`** by
   `tools/config_surface_inventory.py` (L195 hardcodes `bulk_downloader/app.py` +
   `CFG_FIELDS = [...]` regex as the authoritative per-site field list). **Do NOT
   move them** -- consistent with state-stays. (If ever moved, that tool's path+regex
   must change.)

7. **ENDPOINT RENAMING under blueprints (invariant-shaping).** Flask prefixes a
   blueprint view's endpoint: `@app.route` view `api_foo` becomes endpoint
   `domain.api_foo` once in blueprint `domain` (confirmed: live url_map already shows
   `vpn_api.vpn_status`, `settings_center.*`, `cockpit.*`). Consequences:
   - The invariant must key on **(rule, methods, bare-function-name)** -- NOT the
     full endpoint (Section 2).
   - **`url_for` blast radius = ZERO** (no `url_for(` anywhere in the codebase) --
     so the rename breaks no server-side reverse routing.
   - ROUTE_INDEX / ENDPOINT_CATALOG / gui_parity each store `endpoint` + `blueprint`
     + `file` + `line`, so they are **NOT byte-identical** under a move (the
     `(method,path)` stays, the other columns change) -- **they MUST be regenerated
     each cut** (Section 6; this corrects the earlier "0-diff" claim).
   - **8 test files assert `.endpoint`** (`test_contracts` 5, `test_integration_wiring`
     2, the settings_center suites, `test_framework_gui`, `test_v3_61_phase13`,
     `test_v3_66_319_parity_4_5`) -- per cut, update any assertion naming a route in
     this cut's domain to the prefixed name, and band it.
   - **No view function is imported by name in tests** (only helpers) -- so view
     renames don't break test imports; the helper re-export list (finding 8) covers
     the helpers.

8. **Cross-module re-export surface is tiny and enumerable.** Names imported
   `from bulk_downloader.app` by non-blueprint code: production `runner.py` ->
   `_save_sites_config`, `s_cfg` (both stay -> unaffected); tests -> `app`, `s_cfg`,
   `_pairing_tokens`, `CFG_FIELDS`, `DEFAULTS`, `_m2_site_drain_eta`. **Re-export
   watch-list** (keep `from .X import name` in `app.py` when these move):
   `_pairing_tokens`, `_m2_site_drain_eta` (the rest stay in `app.py`).

9. **No custom decorators, no `add_url_rule`, no nested/dynamic routes** (confirmed).
   Views are decorated only by `@app.<verb>`; guards like `_dev_mode_guard()` are
   *called in the body*, not decorators -- so a move carries no decorator-import

10. **Shrink/effort model.** 681 views = **13,427** body lines; 99 helpers = **2,688**

## 2. The invariant -- `route_map_snapshot` (CORRECTED to bare-name)

Behavior-preservation reduces to: **the externally observable routing surface
(rule + methods) is unchanged, and no view function was lost or renamed.** The
endpoint *label* legitimately changes (blueprint prefix, finding 7), so the
snapshot keys on **(rule, sorted methods, bare function name)** -- the endpoint with
any `bpname.` prefix stripped. A clean move => empty before/after diff; a
rename/add/remove/method-change => non-empty.

Verified in-sandbox: 944 rules, deterministic snapshot.

### 2.1 `tools/route_map_snapshot.py` (read-only; ~30 lines)

```python
#!/usr/bin/env python3
"""url_map snapshot for the F5.1 invariant. One sorted line per rule:
"<rule>\t<sorted methods>\t<bare endpoint>" (blueprint prefix stripped, so a
clean move into a blueprint diffs empty). No timestamp/version.

    python3 tools/route_map_snapshot.py > /tmp/before.txt
    # ... one extraction cut ...
    python3 tools/route_map_snapshot.py > /tmp/after.txt
    diff /tmp/before.txt /tmp/after.txt && echo INVARIANT_HELD
"""
import os, sys, importlib
os.environ.setdefault("BD_HOME", os.environ.get("BD_HOME", "/tmp/bd_snap_home"))
os.environ.setdefault("BD_DISABLE_KEEPALIVE", "1")

def snapshot() -> str:
    app = importlib.import_module("bulk_downloader.app").app
    out = []
    for r in app.url_map.iter_rules():
        methods = ",".join(sorted(m for m in r.methods if m not in ("HEAD", "OPTIONS")))
        bare = r.endpoint.rsplit(".", 1)[-1]   # strip blueprint prefix
        out.append(f"{r.rule}\t{methods}\t{bare}")
    out.sort()
    return "\n".join(out) + "\n"

if __name__ == "__main__":
    sys.stdout.write(snapshot())
```

Plus `tests/test_route_map_invariant.py`: freeze the F5.1-OPEN baseline once (the
baseline IS the contract), assert equality each cut. Touch the baseline only at
F5.1-open and at F5.1-close (final surface). The **fail-open registration**
(Section 3) means a silently-failed `register_routes` drops routes from url_map ->
the snapshot diff catches it. Synergy: the invariant also guards against a botched
registration.

### 2.2 What the invariant does NOT cover

Routes identical != handlers identical. A moved view that loses a side effect, a
module-global, an import, or its before_request ordering is still a regression with
an identical surface. So each cut also runs the full targeted suite per touched
domain + the curated band, and the **on-stash full suite** is the binding gate. The
kernel cut additionally proves all 163 `_check_csrf` sites resolve the import.

## 3. Proven pattern + fail-open registration template

From `app_settings_center.py` (1 of 9 precedents): module-level `Blueprint(...)` +
`register_routes(app)` doing `app.register_blueprint(bp)` and returning the count
delta. The registration block (~L18731-18871) wraps each in a **fail-open soft
import**:

```python
# F5.1.N: <domain> routes — extracted from app.py (pure motion).
try:
    from . import app_<domain>
    app_<domain>.register_routes(app)
except Exception as _<domain>_routes_err:
    import sys as _sys
    _sys.stderr.write(f"[app] <domain> routes not registered: {_<domain>_routes_err}\n")
```

Blueprint module header (standard):
```python
from flask import Blueprint, request, jsonify   # + Response/send_file/stream_with_context as needed
# import the INTERNAL leaf modules the views use, directly (NOT from .app):
from .db import ...          # whatever the views call
from .runner import ...      # if needed
from .app_common import _check_csrf   # the CSRF kernel
<domain>_bp = Blueprint("<domain>", __name__)
# ... moved @<domain>_bp.<verb> views (state-touching ones do:
#     from bulk_downloader.app import s_cfg, runners   # inside the body) ...
def register_routes(app):
    before = len(list(app.url_map.iter_rules()))
    app.register_blueprint(<domain>_bp)
    return len(list(app.url_map.iter_rules())) - before
```

**Rules confirmed against the 9 precedents:** blueprints register **no** app-wide
hooks; blueprints **never** top-import `app` (only leaf modules + `app_common`);
full `/api/...` path lives in the decorator (no `url_prefix`); blueprint names are
unique (avoid the 9 taken: vpn_api, widgets_api, captcha_relay_api, live_recorder,
cockpit, cockpit_home, template_manager_ui, data_layer, report_center,
settings_center, framework, fleet). Naming: in-`app.py` `api/vpn` -> `app_egress`
(NOT `app_vpn_api`); in-`app.py` `template*` -> `app_templates` (NOT
`app_template_manager_ui`); in-`app.py` `api/template_manager` API is also distinct
from the extracted `app_template_manager_ui`.

## A14. Endpoint rename -- DEFINITIVELY production-safe (the big closure)

Flask renames a blueprinted view's endpoint to `domain.func`. Exhaustively, nothing
in production depends on the endpoint NAME:

- `url_for(...)` -- **0 uses** anywhere in the codebase.
- `request.endpoint` branches -- **0**. `.view_functions` / `.blueprints`
  introspection -- **0**.
- `request.url_rule` -- 5 uses, **all read `.rule`** (the PATH) or `str(url_rule)`
  (the rule string), never `.endpoint`. Comment at L323 confirms "Keyed by the
  Flask *rule*."
- Route-policy globals are **path-keyed**: `_API_TOKEN_ROUTE_POLICY` maps
  `"/api/capacity": (...)`; `_EXT_VAULT_DATA_ROUTES`, `_SPA_RESERVED_PREFIXES`,
  `_SITES_BULK_ACTIONS` are path/action strings. They stay in the shell (used by
  the `_check_token`/`_check_csrf` hooks) and are unaffected.
- gui_parity's gating flags are **path-derived**: `operator_facing =
  not _is_internal_ep(ep)` where `_INTERNAL_EP_RE = ^/api/(dev|bitrot|circuit|
  crash_recovery|pair|debug|test|_)\b` matches the normalized PATH (`_norm_ep`);
  `spa_wired` matches `/api/...` literals in the FE. So `operator_facing_unwired==0`
  (a gated invariant) is **invariant under blueprinting**.
- `test_gui_parity` `blueprint_module == 3` counts **tools/ blueprints only**
  (cockpit_console + framework_dashboard/fleet) -- NOT `bulk_downloader/app_*.py`.
  Adding domain blueprints does not touch it.

Net consequence: the route docs' **display columns** (`endpoint`, `blueprint`,
`file`, `line`) change -> regenerate ROUTE_INDEX/ENDPOINT_CATALOG/gui_parity each
cut; **no gate flips**. Two routes EMIT endpoint names in their output --
`/api/dev/routes` and `/api/openapi.json` -- a benign output change (operationIds /
the routes listing gain the `domain.` prefix).
