One pass of this list = one F5.1 blueprint extraction. Pairs with
`F5.1_KERNEL_CONTRACT.md` (what may move) and `F5.1_LEDGER.md` (record the result).
Order is load-bearing; the regen sequence especially. Everything runs from

## Per-cut checklist

**0. Pick the cut.** From `APP_DECOMP_MAP.json` / the plan's batch order. Lowest-ripple
first: kernel → trivial domains → state domains → medium families → app_mobile →
giants (api/dev, api/sites) sub-sliced last. ONE cohesive domain (or path-cluster) per
cut. Never batch two app.py groups.

**1. Confirm the domain's path set + cohesion.**
```bash
python3 tools/app_decomp_map.py --domain <name>      # the views + helpers + globals that move
# verify no resource cluster is fractured (split-risk must stay []):
python3 tools/app_decomp_map.py | grep -A2 split-risk
```
Gather by PATH, not name. A path served by 2 handlers → both in this cut.

**2. Create `bulk_downloader/app_<domain>.py`** from the KERNEL_CONTRACT skeleton:
move the view fns (decorator → `@<domain>_bp.<verb>("/api/<domain>/...")`, full path),
carry domain-private helpers + globals, add `def register_routes(app)`. Leaf imports
direct (`from .db import ...`); state access LAZY in-body (`from bulk_downloader.app
import s_cfg`). Blueprint name unique (avoid the 9 taken).

**3. Delete the moved code from `app.py`** and add the fail-open registration block
(KERNEL_CONTRACT) at the registration site (~L18731). Re-export any moved name a test
imports (`from bulk_downloader.app import X`).

**4. Smoke-import + invariant (the prime gate).**
```bash
python3 -c "import bulk_downloader.app"                       # registers cleanly?
python3 tools/cross_monolith_graph.py --check                 # no module-level cycle introduced
# route-map invariant: clean blueprint move diffs EMPTY (prefix stripped):
python3 -c "import sys; sys.argv=['t']; \
  import importlib.util as u; s=u.spec_from_file_location('t','tests/test_route_map_invariant.py'); \
  m=u.module_from_spec(s); s.loader.exec_module(m); \
  m.test_route_surface_unchanged_since_f51_open(); print('route surface OK')"
```
If the surface diffs non-empty → a route was renamed/re-pathed/dropped → fix before
proceeding. (Endpoint-label change alone does NOT diff; the bare-name is compared.)

**5. Update the per-cut test pins (the map lists them).** 0–2 per cut. Grep the
ownership / `.endpoint` pins the moved routes touch and flip the expected blueprint:
```bash
grep -rnE "\.endpoint ==|'(app)'|\"\(app\)\"|blueprint ==|_kb_golden|ownership" tests/ \
  | grep -iE "<domain>|<one of the moved paths>"
# e.g. kb_golden pins /api/library endpoint "(app)" -> "app_library"
```
Update ONLY the pins for routes this cut moved. Leave all others.

**6. Regenerate the in-sync artifacts — IN THIS ORDER (build_route_index LAST):**
```bash
python3 tools/build_function_index.py        # app.py shrinks; test_function_index_in_sync
python3 tools/build_endpoint_catalog.py       # defining file/blueprint changed
python3 tools/gui_parity_inventory.py         # (method,path)-derived; flips operator_facing/spa_wired/csrf labels
python3 tools/build_pin_index.py              # PIN_INDEX (post-bump; see step 8 note)
python3 tools/dependency_graph.py             # new app_<domain> node/edges
python3 tools/check_route_counts.py           # G12: blueprint-count glob vs DEPENDENCY_GRAPH (+1 expected)
python3 tools/build_route_index.py            # ROUTE_INDEX -- ALWAYS LAST (after gui_parity)
```
ROUTE_INDEX / ENDPOINT_CATALOG / gui_parity **regenerate** (this is expected, not a
0-diff cut — the defining file column changes). FUNCTION_INDEX shrinks. DEPENDENCY_GRAPH
gains a node. Guards do NOT change.

**7. Confirm the 7 guard SHAs byte-identical** (from the extracted zip after the cut).
Declare nothing about guards in the CHANGELOG — they didn't move.

**8. Version bump.** `bd-cut` handles the 3-part bump + `__init__` L26 + slice4 pin +
CHANGELOG (ASCII-only; anchor on prev `## v`) + band + `verify_release --zip`.
- Do NOT pre-edit the version or CHANGELOG (bd-cut prepends; a re-run after a mid-build
  abort double-prepends).
- PIN_INDEX/ROUTE_INDEX regenerate AFTER the bump — if bd-cut doesn't fold them, regen
  and re-stage before the zip.

**9. Build over existing dist (no Vite — F5.1 is backend-only).** New `app_<domain>.py`
is auto-included (build_release rglob walk); FRONTEND missing/changed/added = 0.
(Re-minifying unchanged frontend yields different hashes — assemble from the deployed
dist + changed files; do not re-minify.)

**10. Band (from the extracted zip, true `$?`, never piped):**
`test_route_map_invariant` · `test_function_index_in_sync` ·
`test_dependency_graph_in_sync` · `test_endpoint_catalog_in_sync` ·
`test_gui_parity*` · `check_route_counts` (G12) · the cut's domain test(s) · the
ownership/`.endpoint` pin tests touched in step 5 · `test_contracts`.
(bd-cut adds pin/kb/route auto.) Update the band list for the domain you moved.

**11. Full on-stash validation gate.** `capture.sh --workers=90 --summary` — the binding
gate. Must be CLEAN (0 fail) before the cut is "done".

**12. Record in `F5.1_LEDGER.md`:** cut #, module, routes moved, app.py lines
before→after, new route-map snapshot sha (should equal baseline — pure motion),
version, on-stash result, date. Then deploy note (below).

## Recovery notes
- **bd-cut band-tail abort:** if bd-cut dies after the bump but before band/verify,
  do NOT re-run bd-cut (double-prepends CHANGELOG + re-bumps). Resume manually: band
  from the extracted zip, then `verify_release --zip` on true `$?`.
- **Duplicate user message / lost turn:** re-verify what landed (preflight, STATE,
  which artifacts regenerated) before redoing steps.
- **Surface diff you didn't expect:** a blueprint name collision or a missing full
  path silently re-routes — check the ADDED/REMOVED lines the invariant printed.
